# AI解説を接続するときの設計（まだ実装していません）

現在の「③ 問題の整理とAI解説」は **「AI接続前」** です。画面の7項目のうち、「問題の意味」以降はAIを接続するまで作成されません。
このファイルは、将来AI APIを接続するときの約束事です。

## いちばん大事な決まり

| 決まり | 理由 |
|---|---|
| **APIキーは、画面（index.html・GitHub Pages）に絶対に書かない** | 画面のコードは誰でも読めるため、キーが盗まれる |
| AIへの通信は、自分で用意した**サーバー側**を通す | キーをサーバーの環境変数にだけ置くため |
| 送信の前に、**何を送るか説明して、本人が「送る」を押す** | 画像や文章を勝手に外へ出さない |
| 送るのは**本人が確認済みの文章だけ**（画像は送らない） | 確認前のOCR結果を送らない |
| サーバーは受け取った内容を**保存しない・ログに残さない** | プライバシー |

## 構成

```
[iPad Safari：このアプリ]  ──(本人が確認して送信)──▶  [自分のサーバー /api/explain]  ──▶  [AI API]
      GitHub Pages                                      APIキーはここだけ（環境変数）
```

GitHub Pages は静的なページしか置けないので、サーバー側は別に用意します（例：Cloudflare Workers、Vercel の関数など。無料枠のあるものがあります）。

## サーバーのAPI案

`POST /api/explain`

リクエスト（JSON）

```json
{
  "stem": "問題文",
  "choices": [{ "marker": "ア．", "text": "…" }],
  "uncertainLines": ["【要確認】の行"],
  "confirmedByUser": true
}
```

- `confirmedByUser` が `true` でなければ、サーバーは処理せず 400 を返す
- サーバーで文字数の上限（例：4000文字）、1分あたりの回数制限、許可するサイト（Origin）の確認を行う

レスポンス（JSON。画面の7項目に対応）

```json
{
  "meaning": "問題の意味",
  "method": "解き方・考え方",
  "candidates": ["回答候補"],
  "reason": "回答の理由",
  "pitfalls": "間違えやすいポイント"
}
```

「読み取った問題」と「問題の種類」は、いまと同じくブラウザ内で作ります。

## 画面側で行うこと

1. 「AIに解説してもらう」ボタンを追加（「② この内容で合っています」を押したあとだけ使える）
2. 押すと確認画面を出す：「次の文章を、◯◯のサーバー経由でAIに送ります：…　送りますか？」
3. 「送る」を押したときだけ通信する。結果の画面には **「AIが作成した解説です。間違っていることがあります」** と表示する
4. 失敗したときは、「AI接続前」の表示に戻す。AIが答えたように見せかけない

## 守ること

- Classiへのログイン・提出・送信は自動で行わない
- 学校や先生のルールでAIの利用が禁止されているものには使わない
