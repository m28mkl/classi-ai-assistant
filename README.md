# Classi AI Assistant

Classiのスクリーンショットから課題・お知らせ・提出期限を読み取って整理し、AI（Claudeなど）に相談するための**質問文を作る**ブラウザアプリです。`index.html` を開くだけで動きます。AIのAPIを使わなくても、**Claudeアプリなどの回答を貼り付けて、解説と回答の下書きを整理できます（無料）**。

iPadの **Split View** で、左に Classi、右にこのアプリを並べて使えます（[使い方](#ipadでclassiと並べて使うsplit-view)）。

## このアプリがすること・しないこと

| する | しない |
|---|---|
| 画像の文字をブラウザ内で読み取る（OCR） | AIによる自律判断、画像のAI送信 |
| 読み取りに自信がない行を「要確認」と表示する | Classiへのログイン、認証情報の入力・保存 |
| 問題文と選択肢を分けて表示する（選択肢の順番・記号は変えない） | 別アプリの画面の常時監視、バックグラウンド操作 |
| 課題・お知らせ・期限をキーワードで整理・分類する | |
| AIへの質問文を作り、ボタンを押したときにコピーする | 課題の提出、メッセージ送信などClassiの自動操作 |
| 貼り付けたAIの回答を項目に分け、回答の下書きを作る | 回答の自動入力・自動提出 |
|  | 画像・読み取り結果・履歴の外部送信や端末への保存 |

AIに相談するときは、作った質問文を利用者が自分でコピーして貼り付けるか、（AIサーバーを用意した場合は）確認画面で「送る」を押してAIに解説を作らせます。整理結果は自動判定なので、必ず本人がClassiで確認してください。

## 機能

1. 読み取った課題・お知らせをカードで表示
2. 提出期限の近い順に並べる（同じ日は重要なものが先）
3. 期限が読み取れないものは「期限：不明」と表示し、最後に並べる
4. お知らせを「重要／行事・予定／手続き／一般」に分類し、絞り込める
5. iPad Air（縦 820px／横 1180px）向けのレイアウト
6. カードの修正・削除・手動追加
7. 操作履歴の表示（画面を開いている間だけ保持）
8. **Split View対応**：細い幅（320〜800px）でも1列で使え、上に固定した「読み取る／確認／解説／課題」のメニューで移動できる
9. **読み取り結果の確認・修正**：認識に自信がない行を「要確認」（自信度つき、低い単語は黄色）と表示。文章を直すと「修正済み」になる。「この内容で合っています」を押すまで、解説用の質問文は作れない
10. **問題の整理とAI解説**：①読み取った問題（問題文／選択肢）②問題の種類 ③問題の意味 ④解き方・考え方 ⑤重要ポイント ⑥回答候補 ⑦回答の理由 ⑧間違えやすいポイント。①②はキーワードによる自動判定。③〜⑧は、**貼り付けたAIの回答**（無料）か、AIサーバーを接続したときの **OpenAI（gpt-6-luna）** の回答から作ります。どちらもないときは「AI接続前：まだ作成されていません」と表示し、AIが答えたようには見せません
13. **AIの回答の貼り付け（無料・APIなし）**：質問文をコピー → Claudeアプリなどで聞く → 回答を貼り付けて「回答を整理する」。見出しの書き方が違っても、できるだけ項目に分けます
14. **回答の下書き**：AIの回答から下書きを作り、自分で直してコピーできます。Classiへの入力と提出は自分で行います
15. **模擬データ**：「模擬データで試す」で、通信せずに画面の動きを確かめられます（AIの回答ではないと明記）
11. **画像の補正（任意）**：「画像を補正して読み取る」で、グレースケール化とコントラスト調整をしてから読み取る（初期設定はオフ）
12. **画面の内容をすべて消去**ボタン

## iPadでClassiと並べて使う（Split View）

1. Safariでこのアプリのページを開く（共有ボタン →「ホーム画面に追加」しておくと便利）
2. 別のSafariウインドウで Classi を開く
3. 画面上の「…」→「Split View」で、左にClassi、右にこのアプリを並べる
4. Classiの画面でスクリーンショットを撮る（電源ボタン＋音量を上げるボタン）
5. 右のこの画面で「ファイルを選択」→ 写真から選び、「画像を読み取る」を押す
6. 「② 読み取った情報の確認・修正」で、Classiの画面と見比べて直し、「この内容で合っています」を押す

Classiの画面を自動で読み取ることはできません（Webアプリは別アプリの画面を見られないため）。スクリーンショットを選んだときだけ読み取ります。
**学校や先生のルールでAIの利用が禁止されている課題やテストには使わないでください。**

## AIの回答を貼り付けて使う（無料・APIなし）

1. 「② 読み取った情報の確認・修正」で内容を確かめ、「この内容で合っています」を押す
2. 「解説用の質問をコピー」を押す（質問文には、回答の見出しの指定が入っています）
3. Claudeアプリ（またはChatGPT・Geminiなど）を開き、貼り付けて送る
4. 返ってきた回答をすべてコピーし、アプリの「AIの回答を貼り付けて整理する」の欄に貼り付ける
5. 「使ったAI」を選んで「回答を整理する」を押す → 解説の各項目と「回答の下書き」が表示される
6. 下書きを確認・修正して「下書きをコピー」→ Classiには自分で入力し、自分で提出する

貼り付けた文章はどこにも送信せず、端末にも保存しません（ページを閉じると消えます）。

### AIの切り替え（将来のAPI接続）

AIとのやりとりは [`ai-assist.js`](ai-assist.js) にまとめてあります。どのAIでも「質問文を作る → 回答の文章 → 項目に分ける（`parseAnswer`）」という同じ流れです。

- 今あるもの：Claude・ChatGPT・Gemini・その他（すべて手動の貼り付け・無料）、模擬データ
- 将来APIを使うときは、`ClassiAI.registerProvider({ id, label, mode: "auto", cost: "paid", ask(prompt) })` を1つ追加します。`ask` は回答の文章を返すだけでよく、整理・下書き・画面の表示はそのまま使えます
- **有料のAPIを追加するときは、料金を確認してから**にしてください

## AI解説の接続について（OpenAI・予算管理つき・今は使っていません）

`server/` に、AI解説のサーバーがあります（追加パッケージなし）。**APIキーはサーバーの環境変数だけ**で管理し、画面には置きません。

- 確認した問題文だけを、確認画面のあと「送る」を押したときだけ送信（画像は送りません）
- 1回の入力は4,000トークン、出力は800トークンまで／1日50回まで
- **推定利用額が300円**に達したら、アプリ側でAIを停止（利用額と回数は画面に表示）
- 料金は `server/pricing.json`（モデル別の単価と為替）から計算。コードに固定していません
- APIエラー・時間切れ・予算超過のときは、安全なメッセージを出して停止。AIなしの機能は使えます

> **注意：300円は、トークン使用量と料金表からの「推定値」によるアプリ側の制御です。OpenAIの請求を止める上限ではありません。**

設定・動かし方・仕組みは [docs/ai-server.md](docs/ai-server.md) を見てください。

## 対応している日付の書き方

`2026年11月20日`、`2026/11/20`、`2026-11-20`、`2026.11.20`、`11/20`、`11月20日`、全角数字、時刻（`17:00`）。
「明日」「今日」「明後日」は「期限・締切・まで」と同じ行にあるときだけ期限として扱います。
年がない日付は今年として扱い、半年以上前の日付になる場合は来年とみなします。

## 外部との通信

「画像を読み取る」または「動作チェック」を押したときに、OCRに必要な次のファイルだけを CDN（cdn.jsdelivr.net）から取得します。**画像はどこにも送信しません。** 読み取った文字も、AIサーバーを接続していて、確認画面で「送る」を押したとき（確認済みの問題文だけ）以外は送信しません。

| ファイル | 固定しているバージョン |
|---|---|
| OCRライブラリ [tesseract.js](https://github.com/naptha/tesseract.js) `tesseract.min.js`（SRIで改ざんを検出） | 5.1.1 |
| Worker `worker.min.js` | 5.1.1 |
| OCRエンジン `tesseract.js-core`（端末に合わせて SIMD 版／通常版を自動選択） | 5.1.1 |
| 日本語・英語の言語データ `jpn` / `eng`（`4.0.0_best_int`） | tesseract.js 5.1.1 の既定 |

合計で約9MBです。言語データ（公開データ）はブラウザ内にキャッシュされるため、2回目からはダウンロードし直しません。

## OCRの仕組みと過去の不具合

- UMD版の `tesseract.min.js` を `<script>`（バージョン固定・SRI付き）で読み込み、`window.Tesseract.createWorker` を使います。
- 以前は ESM版（`tesseract.esm.min.js`）を `import()` して `createWorker` を取り出していました。ところが ESM版は `default` しかエクスポートしないため、`createWorker` が `undefined` になり、iPad の Safari などで「createWorker is not a function」というエラーになっていました。
- Worker は読み取りのたびに作り、成功・失敗にかかわらず必ず終了します（iPad のメモリを解放するため）。
- 大きすぎる画像は長辺2400pxまで縮小してから読み取ります。
- 認識の自信度（0〜100）が、行は70未満・単語は50未満のものを「要確認」にします（`index.html` の `OCR_CONF`。目安であり、正解・不正解の判定ではありません）。自信度の情報が得られなかったときは、その旨を表示します。
- 日本語のOCRで文字の間に入る空白（例「保 護 者 会」）を取り除いてから、課題の分類や期限の読み取りを行います。

## OCRの精度を上げる処理（`ocr-pipeline.js`）

すべてブラウザ内（Canvas API）で行い、外部には何も送信しません。選んだ画像そのものは変更せず、読み取り用のコピーを加工します。

1. **不要な部分を除外**：画素の特徴（横幅の25%以上続く非白色の帯＝バー・動画プレイヤー・グレーの回答欄・ボタン、青い帯＝ステータスバー・ヘッダー）から、Classiの画面の「UI部分」を見つけて除きます。固定の座標は使わないので、画面の大きさや、ステータスバーの有無、余白が変わっても対応できます（テストで確認）。設定でオフにもできます。
2. **前処理**：本文を切り出し、文字の高さ（行の高さ約56px）に合わせて拡大し、グレースケール化・コントラスト調整をします。読み取りに自信がない部分は二値化（大津の方法）＋ノイズ除去した画像でも読み、確信度の高い方を採用します。
3. **日本語と英語を分けて読む**：1回目（jpn+eng）で単語の位置と文字種を調べ、各行を「日本語の部分」と「英語の部分」に分けます。英語は `eng`、日本語は `jpn` で読み直し、左から右の順番のまま結果をつなげます。同じ言語の部分は1枚の画像にまとめて読むので、処理時間を抑えられます。
4. **英語の誤認識対策（前後の単語を見て判断。一括置換はしない）**
   - 単独の「l」「|」が英単語に挟まれている → 代名詞の「I」
   - 単独の「1」は、文頭や to / that / whom などの後（代名詞の I が来る位置）でだけ「I」。それ以外（例：page 1 of）は**直さずに「要確認」として表示**
   - 「1spoke」「lspoke」のようなくっついた語は、Tesseract の辞書にない場合だけ分けて「要確認」として表示
   - 単語の途中の大文字「I」は、辞書にない語のときだけ小文字の「l」
   - 句読点の前の空白・文末の句読点の後の空白・連続する空白を整え、英文の途中の不自然な改行をつなげます
5. **日本語の後処理**：文字の間の空白を取り除き、半角の括弧・読点を全角にそろえます。単語の間に下線の形が実際にある場合だけ「_」を補います。
6. **問題の構造**：タイトル・問題文・小問・英文・指示・書き換え・選択肢（ア・イ・ウ・エ）に分けます。選択肢の順番や内容（文法の正誤）は変えません。取り違えやすい記号（「工」→「エ」、行頭の「=」→「⇒」など）は、判断した内容を「要確認」として表示します。

読み取った後は「**読み取り結果の確認**」画面で、次のことができます。
- 元の画像と見比べる：除外した部分・読み取った行・自信がない部分が、元の画像に重ねて表示されます
- 項目ごとに直す：問題文・英文・選択肢などを、項目ごとに編集できます
- 自信がない部分と自動修正を確認する：自信がない部分は元の画像から切り出して、確信度と一緒に表示されます。自動で直した箇所の一覧も確認できます
- 修正前と修正後を比較する：2つを並べて違いを表示します

内容を確かめてから「読み取った情報に反映」を押してください。

### 実行方法

Node.js（22で動作確認済み）が必要です。

```bash
npm ci                                  # 依存パッケージのインストール
npx playwright install chromium         # 初回のみ：テスト用ブラウザのインストール
npm test                                # すべてのテスト
npm run test:unit                       # 単体テストだけ
npm run test:e2e                        # iPad Air の画面テストだけ
npm run test:server                     # AI解説サーバーのテストだけ
npm run test:splitview                  # 細い幅（Split View・スマホ）の画面テストだけ
npm run test:ocr                        # OCRのテストだけ（本物のOCRを含む・オフライン）
npm run test:ocr:online                 # CDN上の本物での確認も含める（インターネット接続が必要）
npm run check:syntax                    # JavaScript の構文チェックだけ
```

Linux で必要なライブラリが足りないときは `npx playwright install --with-deps chromium` を使ってください。
Safari と同じエンジン（WebKit）で OCR テストを実行するときは、`npx playwright install webkit` のあと `OCR_WEBKIT=1 npm run test:ocr -- --project=ocr-webkit` を実行します。
アプリを手元のブラウザで確認するときは `npm run serve` を実行し、`http://127.0.0.1:8765/` を開きます。

### 自動テスト（GitHub Actions）

`.github/workflows/test.yml` により、プルリクエストの作成・更新時と main への push 時に、Chromium と WebKit（Safari と同じエンジン）で、CDN上の本物での確認も含めたすべてのテストが自動で実行されます。Actions タブから手動でも実行できます。結果は GitHub の「Actions」タブで確認でき、テストレポート（画面のスクリーンショットつき）は `playwright-report` としてダウンロードできます。

## iPad Air の Safari での実機テスト（日本語OCR）

自動テストは Chromium と WebKit（Safari と同じエンジン）で行っていますが、iPad 実機の Safari とは同じではありません。新しいOCR処理を変更したときは、次の手順で実機でも確認してください。

### 1. iPad でアプリを開く

- **main にマージ済みの場合：** GitHub Pages の公開URL（リポジトリの Settings → Pages に表示）を iPad の Safari で開きます。
- **マージ前のブランチを試す場合：** PC（Mac/Windows）でこのリポジトリのブランチを開き、iPad と同じ Wi-Fi につないで次を実行します。

  ```bash
  npm ci
  HOST=0.0.0.0 npm run serve
  ```

  表示された `http://192.168.x.x:8765/` を iPad の Safari で開きます。同じネットワークの端末から開ける状態になるので、確認が終わったら Ctrl+C で止めてください。
  （http で開くため、「AIへの質問をコピー」は自動コピーの代わりに文章を選択する動きになります）

初回はOCRの部品（約9MB）をダウンロードするので、Wi-Fi で試してください。

### 2. 動作チェック（個人情報なし）

1. 「① 画面を読み取る」の「OCRが動くか確認する（サンプル画像で動作チェック）」を開きます。
2. 「動作チェックを実行」を押します。実行中はボタンが押せなくなり、「日本語・英語の言語データを読み込み中...（○%）」のように進み具合が表示されます。
3. **「成功：日本語と英語を読み取れました」** と、4項目すべてに ✓ が付くことを確認します。所要時間も表示されます。

### 3. サンプルのスクリーンショットで確認

1. iPad の Safari で `（アプリのURL）/tests/fixtures/ocr-sample-ja.png` を開き、画像を長押しして「"写真"に保存」します（架空の内容の画像です）。
2. アプリに戻り、「ファイルを選択」→ 保存した画像を選んで「画像を読み取る」を押します。
3. 「読み取った情報」に、次のような内容が表示されることを確認します。自動テスト（Chromium）では次のとおりでした。空白や記号の細かな違いは問題ありません。

   ```
   お知らせ・課題一覧
   数学課題プリント3
   提出期限 : 2026年11月20日 17:00
   【重要】保護者会のお知らせ
   English Homework p.10
   ```

4. 「情報を整理する」を押し、「数学課題プリント3」のカードに「期限：2026年11月20日（金） 17:00」、「【重要】保護者会のお知らせ」のカードに「お知らせ」「重要」が付くことを確認します。
   （見出しの「お知らせ・課題一覧」も「課題」という言葉を含むのでカードになります。不要なカードは削除してください）
5. もう一度「画像を読み取る」を押し、1回目より速く終わる（言語データを再ダウンロードしない）ことを確認します。

### 4. Classi の問題画面のサンプルで確認

1. iPad の Safari で `（アプリのURL）/tests/fixtures/classi-like-q01.png` を開き、写真に保存します（架空の問題画面です。実在の教材ではありません）。
2. 保存した画像を選んで「画像を読み取る」を押します。
3. 「読み取った情報」が、次のような内容になることを確認します（空白や記号の細かな違いは問題ありません）。

   ```
   練習問題_関係代名詞と前置詞A
   次の問いに答えなさい。
   小問01
   次の英文を指示にしたがって書きかえるとき、（ ）に入るものを選びなさい。
   This is the park. I played in it last week. （一つの文に）
   ⇒This is the park (     ) last week.
   選択肢
   ア in I played which
   イ which in I played
   ウ in which I played
   エ I played which
   ```

4. 「② 読み取った情報の確認・修正」の「元の画像と見比べて直す（くわしい確認）」で、次のことを確認します。
   - 元の画像の上部（ステータスバー・ヘッダー・動画）と下部（回答欄・ボタン）が、灰色の「除外した部分」になっている
   - 選択肢がア・イ・ウ・エの順に並んでいる
   - 推測で直したところ（例：行頭の記号を「⇒」と判断）があれば、「要確認」の一覧に表示されている
5. 所要時間も確かめてください。PC では、改善版の読み取りに1枚あたり約3〜7秒かかります。iPad ではこれより長くかかる可能性があります。

### 5. 実際の Classi のスクリーンショットで確認

Classi の画面をスクリーンショットして読み取ります。画像と読み取り結果は iPad の外に送信されません。

### 6. 確認する項目

| 確認する項目 | 期待する結果 |
|---|---|
| 動作チェック | 「成功」と表示される |
| 「createWorker is not a function」などのエラー | 表示されない |
| 読み込み中のボタン | 「画像を読み取る」「ファイルを選択」「動作チェックを実行」が押せない |
| 2回目の読み取り | 1回目より速い |
| Classi の問題画面のサンプル | 上の手順4の内容と一致し、確認画面で元の画像と見比べられる |
| 機内モードで初めて読み取ったとき | 「読み取りエラー：OCRライブラリを読み込めませんでした…」などの分かりやすいエラーが表示され、ボタンが元に戻る |

### うまくいかないとき

- 表示されたエラーメッセージと、動作チェックの結果（認識結果・所要時間）をスクリーンショットしてください。
- Mac があれば、iPad の「設定」→「アプリ」→「Safari」→「詳細」→「Webインスペクタ」をオンにし、Mac の Safari の「開発」メニューから iPad のページを選ぶと、コンソールのエラーを確認できます。
- コンテンツブロッカーを使っている場合は、cdn.jsdelivr.net を許可してください。
